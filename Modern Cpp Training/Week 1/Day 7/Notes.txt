In a class diagram , there is a member function in the functionalities section with notation "Display : void " .
This implies : 
                - Display can be ignored
                - Display returns void 
                - Display takes no parameters 


Association -- There is no concept of inheritance in it . But there is a relationship b/w them 
            Ex : Debit Card and Bank Account --[ Every Bank Account has a linked Debit Card ]
            Ex : FLight and Plane ---- [Every flight has a plane ]
        Represent by solid line only , no arrow ------------> Both the classes are aware of each other in bidirectional Association 
        Represent by solid line , with (->)arrow --------------> Both the classes are aware of each other in 
            uni - directional Association  . The arrow point out to the known direction 


Interface -- Its represent by dotted lines with a unfilled arrow (Triangle)

Aggregation : [has a relation -- if you destroyed the car , you not need to destroy the wheels]
                use references
            -->  represented by the unfilled diamond 
            : Ex =>    [car]<>------->[wheel]
                                     4

                A car is aggregated by the 4 wheels. 
                    diamond is point to the thing which is aggregated.
                    arrow 

Composition : Same meaning 
            use pointers 
            --> represented by the filled diamond

            : Ex =>  [Company]<::>--------------->{Department}

Notes : 1) WHen the return - type is not mentioned , assume it void 
        2) in -- used to give context in the parameters
        3) solid line with unfilled arrow --- represent Inheritance  ----[arrow point out to the base class ]
        4) Italics word in the base class represent the abstract class ---(Base )
        5) Member function in the abstract base class which is written in italics represent virtual class 
        6) + public
        7) # protected 
        8) - private
        8) ~ package

diamond shaped -- represent the decision 
swim lanes --- the horizontal parts of the system

flow node -- takes one inpout then have multiple outputs 
join node -- takes multiple input then have one outputs
